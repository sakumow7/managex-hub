# Deploy the portfolio for $0

Use a **Render Free Web Service** for FastAPI, a **Render Static Site** for React, and a **Neon Free project** for PostgreSQL. No paid disk, cron service, background worker, or Render database is required. Free tiers have usage limits and may change; this is a low-traffic portfolio configuration, not a promise of unlimited hosting.

The public version opens a temporary workspace with fictional tickets for each visitor. It needs no public password or administrator account. Workspaces expire after one hour; expired data is removed at the next workspace creation or server startup. Up to 30 workspaces and 100 successful changes per workspace bound storage growth. Idle expired records may remain stored until that cleanup runs, but are no longer accessible.

## 1. Create the free database

1. In [Neon](https://neon.com), create a project on the **Free** plan, selecting PostgreSQL 17 and a region near your Render API (the blueprint uses Virginia).
2. In Connect, copy the connection string for your project's default database. Prefer the **direct/unpooled** connection for this small single-process app so the same URL works for Alembic and PostgreSQL transaction locks. Keep `sslmode=require` and any other Neon-supplied TLS parameters.
3. Store the URL only in Render's environment settings. Do not put it in Git, the frontend, screenshots, or chat. Plain `postgresql://` URLs are normalized to the psycopg 3 driver by the application.

Use a dedicated database for this demo. Do not connect it to the database for the original internal application. Neon's current Free plan has 0.5 GB per project and monthly compute/transfer limits; select Free rather than a metered paid plan. [Official Neon plan source](https://github.com/neondatabase/website/blob/main/content/docs/introduction/plans.md)

## 2. Deploy the API

Push the portfolio changes to your GitHub repository. In Render choose **New → Blueprint**, connect the repository, select the branch containing these changes, and use `render.yaml`. Check that the proposed service is **Free**. This blueprint creates only the API and prompts for DATABASE_URL. JWT_SECRET is generated by Render.

Alternatively create the web service manually:

| Setting | Value |
| --- | --- |
| Service type | Web Service |
| Root directory | `backend` |
| Runtime | Python 3 |
| Instance type | **Free** |
| Build command | `pip install -r requirements-lock.txt` |
| Start command | `python -m app.start` |
| Health check path | `/api/live` |
| PYTHON_VERSION | `3.12.14` (the local verification version) |
| DATABASE_URL | Neon direct connection URL with TLS |
| JWT_SECRET | A generated random secret of at least 32 characters |
| DEMO_ENABLED | `true` |
| CORS_ORIGINS | `[]` initially; update after the frontend is created |
| DEMO_MINUTES / DEMO_MAX_WORKSPACES / DEMO_MAX_MUTATIONS | `60` / `30` / `100` |

The startup command applies Alembic migrations before serving and cleans expired demos. It uses Render's PORT automatically. There is no paid pre-deploy command or shell step, and **you do not run the original app.seed for public hosting**: each visitor gets fresh scenarios on demand.

Copy the API URL Render assigns, for example `https://your-unique-api.onrender.com`. Confirm `/api/live` returns status ok. Check `/api/health` once to verify database connectivity. Platform probes use `/api/live` to avoid continually waking Neon; user-initiated demo launches check `/api/health`.

## 3. Deploy the static frontend

In Render choose **New → Static Site**, connect the same repo and branch:

| Setting | Value |
| --- | --- |
| Root directory | `frontend` |
| Build command | `npm ci && npm run build` |
| Publish directory | `dist` |
| NODE_VERSION | `22` |
| VITE_DEMO_MODE | `true` |
| VITE_API_BASE_URL | Your actual API URL followed by `/api` |

Do not select Web Service for the frontend. A Static Site serves the portfolio entry page even when the API is asleep. These VITE variables are public build-time values; never put the database URL or JWT_SECRET in a VITE variable. Changing them requires rebuilding the static site.

No application routes currently require an SPA rewrite: navigation uses local React state. If you later add URL-based routes, add Render's `/* → /index.html` rewrite. The API is called using its separate absolute URL.

## 4. Connect the allowed origin

Copy the frontend URL Render actually assigns. In the API service's environment settings, change CORS_ORIGINS to a JSON array containing that exact origin, with no trailing slash:

```json
["https://your-unique-frontend.onrender.com"]
```

Save and redeploy the API. If you later add a custom domain, explicitly add that origin too. Do not use `*`. CORS is browser access configuration; authentication and workspace/role policies remain enforced independently by the backend.

## 5. Verify the public demo

1. Open the static frontend in a private browser window. Its introduction and source link should load immediately.
2. Choose Supervisor and launch. The first API start may take about a minute; the UI displays progress and waits up to roughly 100 seconds for readiness. It does not run a keep-awake service.
3. Assign the printer ticket. Switch to CST agent, add an internal note, then switch to Requester and verify that note is absent.
4. Open a separate browser/private context and launch again. Your first visitor's changes must be absent.
5. Reload within the same tab and continue the same workspace. After expiry, launch a fresh one.
6. Check the browser network panel for CORS failures and mixed-content requests. Both URLs should use HTTPS.
7. Confirm Render and Neon still show their Free plans. Add the frontend URL to your GitHub repository's Website field and portfolio page.

## Cost and capacity behavior

Render's free API sleeps after 15 minutes without incoming traffic, and free instance hours/bandwidth/build limits apply. Its free PostgreSQL database expires after 30 days, which is why this setup uses Neon. Without a Render payment method, billable overages disable services instead of charging; adding one can change that behavior. Stay on Free plans and review provider usage. [Render free limits](https://render.com/docs/free), [Render billing FAQ](https://render.com/docs/faq)

If all 30 demo slots are occupied, new visitors see a useful capacity message while existing visitors continue. Slots become available when expired workspaces are cleaned on the next creation attempt. This bounds application storage but is not a comprehensive abuse-prevention service. Provider quotas can still suspend a heavily accessed public demo. A short recorded walkthrough alongside the live link helps visitors when the free service is unavailable.

## Updates and rollback

Keep frontend/backend DEMO mode settings aligned. Test in a separate disposable database, push the change, and deploy the API before a frontend that depends on new endpoints. Migrations are additive and retain existing normal accounts/tickets with null workspace IDs. To roll back a schema change, restore a verified backup to a separate database and deploy its matching code; the migrations deliberately do not drop data in downgrade.

Keep the generated JWT secret stable across normal redeploys. Rotating it invalidates active demo tokens. Do not expose an administrator persona or enable password login on a public demo deployment.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| Original login page appears | Set VITE_DEMO_MODE=true and rebuild frontend |
| Demo endpoints return 404 | Set DEMO_ENABLED=true on API and redeploy |
| CORS error | Correct exact frontend origin in API CORS_ORIGINS JSON |
| Frontend calls its own /api | Set hosted VITE_API_BASE_URL and rebuild |
| Server starts but demo stays unavailable | Check `/api/health`, DATABASE_URL TLS and migration logs |
| Database missing psycopg2 | Use supported postgresql:// normalization or explicit postgresql+psycopg:// |
| Capacity message | Wait for workspace expiry; avoid raising caps without reviewing free quotas |
| Role switch asks for new demo | The workspace/token expired or JWT_SECRET changed |

The reference Docker Compose setup remains available for local learning; it is not required on Render.
